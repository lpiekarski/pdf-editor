# PDF Editor

A PDF editor that runs entirely in the browser — desktop and phone. Files are never uploaded: the app is a set of static files and makes no network requests after it loads, so it works offline as an installable web app.

## Features

**Editing (WYSIWYG)**
- Add text in any of the bundled fonts (Noto Sans/Serif/Mono — full Polish/Latin-Extended support), images, rectangles, ellipses, lines, arrows, freehand drawing, white-out boxes and sticky notes.
- Highlight, underline and strike out existing text. These are saved as real PDF annotations, so they stay editable in other readers.
- Select and delete annotations that were already in the PDF.
- Optionally save added objects as editable annotations instead of flattening them (save dialog).
- Select, move, resize, rotate, duplicate, reorder and delete; undo/redo; keyboard shortcuts; long-press menu on touch screens.
- On-screen text uses the same font files and the same line breaking as the exported PDF, so what you see is what you get.

**Forms**
- PDFs with form fields: fill text fields, checkboxes, radio buttons, dropdowns and lists in place. Optionally flatten them on save.
- PDFs without form fields: **Fill form** mode finds the blanks (drawn lines, `____` and `.....` leaders, `Label:` gaps, checkboxes, boxes). Tap one to type or tick it; text snaps onto the line.
- **Make fillable PDF** turns the detected blanks into real form fields.

**Signatures**
- Graphical signature: draw (mouse, finger or stylus with pressure), type in a script font, or upload a photo (the paper background is removed automatically). Saved signatures stay on the device (IndexedDB).
- Digital signature: PAdES-B-B (`ETSI.CAdES.detached`, SHA-256, signing-certificate-v2) with a `.p12`/`.pfx` certificate file. Modern AES files and legacy 3DES files (Windows exports) are both supported.
  - Visible signature: your handwritten signature plus name, date and reason. It can go in an existing empty signature field or a default box, or the signature can be invisible.
  - Approval or certification signatures (DocMDP levels 1–3), optionally locking all form fields (FieldMDP). Several signatures in one document.
- Opening a signed PDF (from any tool) automatically:
  - shows a banner with the overall status;
  - puts badges on visible signature fields;
  - fills a signature panel with signer, times, reason/location, level, integrity, cryptographic validity, changes made after signing and whether they were allowed, the certificate chain (exportable) and any revocation data;
  - offers **View signed version**, which opens exactly what each signer signed.
- Edit guard: on a signed file, changes are saved as incremental updates, so the signed revision stays intact. You are told which changes keep the signatures valid. Certified "no changes" documents are protected from edits, and fields locked by a signature are read-only.

## Limits (by design or for now)

- Only PAdES-B-B: no timestamps, OCSP or CRL fetching (B-T and above), because those servers refuse direct browser requests (CORS) and the app is static-only. Existing B-T/LT/LTA signatures from other tools are still displayed.
- No eIDAS qualified signatures, smart cards or cloud signing.
- Certificate trust is not checked against a trust store. The panel shows the chain and says "Trust: not checked".
- Signing keys: RSA only (the PKCS#12 loader does not support EC keys).
- The PDF's own existing text cannot be edited in place. Use white-out plus new text instead. **White-out only hides content visually** — the text underneath remains in the file (the save dialog warns about this).
- XFA forms, and signing or editing encrypted PDFs, are not supported. Password-protected PDFs can be opened and viewed.
- Field detection is heuristic and works on vector PDFs. Scanned pages have no lines to detect, so you place text manually.

## Development

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # unit/integration tests (Vitest)
npm run e2e          # end-to-end tests (Playwright: desktop Chromium, Android Chromium, iPhone WebKit)
npm run build        # static site in dist/
```

The signing and export tests also validate the output with independent tools when a Python venv is present. Without the venv, those checks are skipped.

```bash
python -m venv .venv
.venv/Scripts/pip install "pyhanko[opentype]" pyhanko-certvalidator pikepdf   # Windows (.venv/bin/pip elsewhere)
```

Test data is regenerated by `npm run fixtures` (PDFs), `npm run certs` (throwaway test PKI, password `test`) and `python tools/sign_fixture.py` (reference files signed with pyHanko).

### Deploying

Any static host works. The included GitHub Actions workflow runs all tests and publishes to GitHub Pages; set `BASE_PATH` when the site is served from a sub-path.

## Architecture

| Area | Where | Notes |
|---|---|---|
| Rendering | `src/viewer` | pdf.js; lazy, memory-capped canvases (iOS-safe); `coords.ts` maps view ↔ PDF space (rotation, CropBox), tested against pdf.js |
| Editor model | `src/model`, `src/editor` | Objects stored in view units (top-left origin), undoable store, overlay layer per page |
| Export | `src/export` | Everything is appended as an **incremental update** (`src/pdf/incremental.ts`), never a rewrite |
| Forms | `src/forms` | AcroForm read (pdf.js) / write (pdf-lib), blank detection from operator lists, conversion to fields |
| Signing | `src/signature` | `cms/p12.ts` (node-forge → WebCrypto), `cms/cades.ts` (pkijs), `pdf/sign.ts` (placeholder, ByteRange, injection), `verify/analyze.ts` (validation and change classification) |
